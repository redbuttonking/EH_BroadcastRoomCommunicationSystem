# EH_BroadcastRoomCommunicationSystem

EH 방송실 커뮤니케이션 시스템 프로젝트입니다.

이메일 인증과 관리자 승인을 모두 마친 계정만 이용합니다. 기존 계정도 메일의 인증 링크를 연 뒤 화면에서 ‘인증 완료 확인’을 한 번 눌러야 합니다. 기존 승인과 빠른 문구는 유지됩니다.

관리자 승인 방식으로 운영합니다. 신규·기존 일반 계정 모두 관리자가 승인해야 방을 이용할 수 있습니다. 관리자는 로그인하면 기본 홈으로 들어가며, ‘가입 승인 관리’ 버튼에서 신청을 승인·거절하거나 승인을 취소합니다. 관리자 계정의 대화 역할은 고정하지 않습니다. 새 방을 만들면 방송실로 입장하고, 기존 방에는 입장할 때마다 방송실·예배인도자를 선택할 수 있습니다. 승인 결과는 접속 중인 화면에 바로 반영됩니다. 상세 상태는 [개발 기록](docs/development.md)의 마지막 항목을 참고합니다.

React와 Firebase 기반의 첫 구현입니다. 두 브라우저에서 비밀번호 입장, 문구 버튼·채팅, 재입장, 방 유지·삭제를 확인할 수 있습니다. 실제 Firebase 프로젝트와 싱가포르 데이터베이스 생성, 이메일·비밀번호 인증 설정, 보안 규칙과 웹사이트 배포를 완료했습니다. 공개 주소에서도 입장·양방향 메시지·재입장·방 삭제를 검증했습니다.

서비스 주소: [은혜장로교회 예배소통 시스템](https://eh-worship-chat.web.app). 홈에서 역할을 선택해 회원가입하고 관리자 승인을 받은 뒤, 이후 같은 계정으로 로그인합니다. Firebase 콘솔에서 일반 계정을 만들 필요는 없습니다. 승인된 방송실 계정은 PC에서 방을 만들고, 승인된 예배인도자 계정은 휴대폰에서 같은 방을 선택해 방 비밀번호로 입장합니다. 휴대폰은 가로로 사용합니다. Firebase가 웹사이트를 제공하므로 개발 PC를 켜 둘 필요는 없습니다.

## 로컬 실행

Node.js 22.12 이상과 Java 21이 필요합니다. Windows PowerShell에서 스크립트 실행 정책 오류가 나면 `npm` 대신 `npm.cmd`를 사용합니다.

```sh
npm ci
npm run dev:local
```

`http://127.0.0.1:5173`을 서로 다른 브라우저 창에서 엽니다. 테스트 계정을 하나 가입한 뒤 별도 터미널에서 `npm run local:admin -- 가입한테스트이메일`로 그 계정을 로컬 관리자로 지정합니다. 이 명령은 localhost의 demo 에뮬레이터만 변경합니다. 이후 다른 시험 계정은 관리 화면에서 승인합니다. 승인된 방송실은 방을 만들고, 예배인도자는 같은 방 비밀번호로 들어갑니다. 종료는 터미널의 Ctrl+C입니다.

명령이 Firebase Authentication·Realtime Database 에뮬레이터와 웹 개발 화면을 함께 실행합니다. Firebase CLI 로그인·결제 등록·실제 Firebase 프로젝트 없이 시험할 수 있습니다. 화면의 회원가입은 로컬 에뮬레이터 안에만 계정을 만듭니다. 교회 Mac에 상시 서버를 두는 운영안이 아닙니다. 로컬 에뮬레이터 프로세스를 종료하면 시험 데이터는 사라집니다.

현재 PC의 `.env.local`에는 실제 `eh-worship-chat` 연결 설정이 있습니다. `npm run dev` 또는 `npm run build` 후 `npm run preview`는 실제 Firebase에 연결합니다. 에뮬레이터 확인에는 `npm run dev:local`을 사용합니다. `.env.local`은 Git에 포함되지 않으므로 다른 PC는 [Firebase 연결 안내](docs/firebase-setup.md)를 참고해 설정합니다.

## 현재 구현

- 방을 만드는 계정마다 유지 가능한 방 최대 3개. 기존 방은 자동으로 삭제하지 않음
- 실제로 자리를 점유한 참여자에게만 대화 접근 허용. 퇴장 후 다시 입장하기 전까지 조회 차단
- 최근 대화 100개를 먼저 표시하고 ‘이전 대화 보기’로 추가 조회. 서버에서도 조회 범위와 0.5초 전송 간격 검사
- 관리자는 홈에서 참여자가 없는 방을 확인 후 삭제 가능. 참여 중인 방의 강제 삭제는 차단
- 지원 기기에서 사용자가 켤 수 있는 화면 꺼짐 방지. 방을 나가면 해제

- 홈 카드의 이메일 로그인·회원가입·비밀번호 재설정, 로그인 유지와 별도 로그아웃
- 새 접속 시 익명 계정을 만들지 않으며, 회원가입한 계정을 다시 사용
- 관리자 전용 승인·거절·승인 취소 화면, 승인 전 방 목록·입장·대화의 서버 차단

- 좌측 대화·우측 빠른 문구의 공통 화면, 예배인도자 휴대폰 가로 화면 안내
- 일반 계정은 가입 시 역할 유지, 관리자는 방 입장마다 역할 선택. 이름을 직접 정하는 방 생성·목록·비밀번호 입장, 일반 채팅과 문구 전송
- 방마다 방송실 1명·예배인도자 1명으로 동시 입장 제한, 퇴장·연결 종료 확인 후 다른 접속 허용
- 대화 가운데 입장·퇴장·연결 끊김 알림 표시, 방 유지 중 재입장해도 알림 기록 유지
- 홈 ‘내 빠른 문구’와 방 안 ‘빠른 문구 → 편집’에서 추가·수정·삭제·화살표 및 드래그 순서 변경. Firebase에 계정·역할별 저장하고 다른 기기에도 반영
- 일반 사용자는 본인 역할의 문구를 편집하고, 관리자는 방송실·예배인도자 문구를 각각 편집. 다른 사람의 문구에는 관리자도 접근할 수 없음
- 이동한 문구의 테두리 강조, 스크롤 중에만 나타나는 가는 스크롤바, 고정된 편집창 저장 버튼
- 홈 화면에 설치해 주소창 없이 실행하는 웹앱(PWA), 작은 화면에서도 메시지 입력창 유지
- 글자 크기 16~24px 조절과 같은 높이의 문구 버튼, 선택적 기기 내 글자 설정 저장
- 방송실 나가기에서 ‘방을 유지하고 나가기’·‘방을 완전히 닫기’ 선택
- 네트워크 끊김·브라우저 종료 시 방과 대화 유지, 재입장 시 기록 복원
- 방을 만든 방송실 계정만 방 닫기 가능, 닫으면 방·대화·입장 검증 정보·목록을 함께 삭제
- 재연결 안내, 같은 메시지 재시도 중복 방지, 입력 중 문장·스크롤 위치 유지
- 다크/화이트 모드 전환과 선택적 기기 내 설정 저장
- Lucide SVG 아이콘과 Radix Slot/CVA 기반 UI 컴포넌트. 이모지·유료 디자인 에셋·외부 폰트 요청 없음

브라우저 테스트에서 생성하는 화면 미리보기는 로컬 `artifacts/preview/`에 저장하며 Git에는 포함하지 않습니다. 처음에는 운영체제의 색상 설정을 따르고 이후에는 사용자가 고른 모드를 유지합니다. 빠른 문구는 계정의 역할별 최대 30개, 문구 120자이며 분류는 사용하지 않습니다. 방을 닫거나 브라우저 데이터를 지워도 계정에 저장한 문구는 남습니다. 기존 기기 문구는 편집창에서 ‘이 기기 문구 가져오기’를 누른 후 저장하면 계정으로 옮길 수 있습니다. 공유 기기의 문구가 다른 계정에 자동으로 복사되지 않도록 가져오기는 사용자가 선택합니다. 두 기기에서 동시에 수정하면 나중 저장은 충돌을 안내하고 편집 내용을 유지합니다. 인터넷 연결과 서버 저장 확인이 끝나야 편집창을 닫습니다.

휴대폰에서는 첫 화면의 ‘앱 설치 안내’를 사용합니다. Android Chrome 메뉴에서 ‘홈 화면에 추가’ 또는 ‘앱 설치’, iPhone Safari 공유 메뉴에서 ‘홈 화면에 추가’를 선택하고 설치된 아이콘으로 실행합니다. 설치형 웹앱도 인터넷 연결이 있어야 대화할 수 있습니다. 오프라인 안내 파일만 캐시하며 대화·비밀번호·Firebase 응답은 서비스 워커에 저장하지 않습니다.

일반 계정의 방송실·예배인도자 역할은 가입 시 정해지며 이후 임의로 바꿀 수 없습니다. 관리자는 이전에 저장한 계정 역할이 있어도 두 역할로 참여할 수 있습니다. 이 선택은 해당 방의 입장 역할이며 계정 역할을 변경하지 않습니다. 방 안에서는 한 역할로 대화하고, 나간 뒤 재입장할 때 다른 역할을 선택할 수 있습니다. 관리자도 역할별 한 명 제한과 방 비밀번호, 방 생성자의 종료 권한을 따릅니다. 승인 관리 권한은 방송실 역할과 별도로 지정하며, 일반 방송실 계정은 가입자를 승인할 수 없습니다. 가입에 사용한 이메일로 비밀번호 재설정 안내를 받을 수 있습니다. 방에서 나와도 로그인은 유지되며, 로그아웃하면 같은 브라우저의 다른 탭도 로그아웃됩니다. 다른 기기의 로그인에는 영향을 주지 않습니다. 브라우저 저장이 차단되면 현재 창에서만 로그인하고 안내를 표시합니다. 기존 익명 계정은 이번 전환에서 삭제하지 않았습니다.

서버는 사용자 선택에 따라 Firebase만 사용합니다. 이전의 ‘모두 나가면 자동 삭제’ 정책은 이번 대화에서 ‘방송실이 명시적으로 닫을 때 삭제’로 바뀌었습니다. 방을 만든 방송실 계정은 재입장 후에도 방을 닫을 수 있지만 다른 방송실 계정은 닫을 수 없습니다. 실제 프로젝트 ID는 `eh-worship-chat`입니다. Google이 한글 관리용 이름을 거절하여 사용자 확인 후 ‘EH Worship Chat’으로 생성했습니다. 서비스 화면 이름은 ‘은혜장로교회 예배소통 시스템’이며, 데이터베이스 위치는 사용자가 선택한 싱가포르입니다. 결제 계정 연결 없이 구성했습니다.

설치 이름은 ‘예배 소통 시스템’, 홈 화면에 표시할 짧은 이름은 ‘예배소통’입니다. 지원하는 환경에서는 전체 화면으로 실행하고 방 상단의 전체 화면 버튼도 사용할 수 있습니다. 상태바 숨김은 OS·브라우저 지원에 따라 다릅니다. 특히 iPhone에서 상태바가 사라진다고 보장하지 않습니다. 기존 설치의 이름과 표시 방식 반영에는 기기의 앱 업데이트 또는 재설치가 필요할 수 있습니다.

[승인된 아이콘 원본](artifacts/icon-concepts/worship-communication-v1.png)을 파비콘·설치 앱 아이콘·화면 로고에 적용했습니다. `npm run build:icons`는 원본을 그대로 축소해 16/32px PNG와 16/32/48px ICO, iPhone용 180px PNG, 앱용 192/512px PNG를 다시 만듭니다. 실행에는 Playwright Chromium 설치가 필요합니다.

## 검증

```sh
npm run build
npm test
npx playwright install chromium
npm run test:e2e
```

브라우저 설치 위치를 프로젝트 안으로 맞추려면 PowerShell에서 설치 전에 `$env:PLAYWRIGHT_BROWSERS_PATH = '.cache/ms-playwright'`를 설정합니다. 테스트 설정도 이 경로를 사용합니다.

Firebase 보안 규칙과 이전 자동 삭제 후보 방식 실험도 로컬 에뮬레이터로 실행합니다.

```sh
npm run test:firebase
```

[개발 범위와 검증 기록](docs/development.md)에 구현 방식과 제한을, [Firebase 연결 안내](docs/firebase-setup.md)에 실제 Spark 프로젝트 연결 절차를 적었습니다. 실제 Safari·목사님 휴대폰 검증은 아직 남아 있습니다.

## 저장소 구성

- `.gitignore`: 환경 변수, 로컬 설정, 임시 파일의 Git 업로드 제외 규칙
- `.gitattributes`: Git에서 관리하는 파일의 줄바꿈 규칙
- `.editorconfig`: 편집기의 문자 인코딩과 공백 규칙
- `src/`: React 화면, 메시지·문구·글자 설정, 서버 연결 클라이언트
- `src/lib/firebase-client.ts`: Firebase 인증·실시간 수신·방과 메시지 처리
- `tests/`: 방 동작·재연결·브라우저·Firebase 에뮬레이터 실험
- `firebase/`: 비밀번호 입장·역할·메시지·동시 삭제 접근 규칙

## 작업 규칙

- GitHub 자동 검사와 수동 실행 배포 워크플로를 준비했다. 배포용 클라우드 권한 연결과 공개 저장소 반영은 별도 확인이 필요하며, 아직 GitHub에서 실행을 검증하지 않았다.
- 직접 배포에는 `npm run build:production`으로 실제 프로젝트 설정을 확인한다. 운영 설정 백업과 복구 순서는 [Firebase 연결 안내](docs/firebase-setup.md)의 마지막 항목을 참고한다.

- 기본 브랜치는 `main`입니다.
- 비밀번호와 API 키는 코드에 직접 넣지 않고 `.env` 등 로컬 환경 설정으로 관리합니다.
- 필요한 환경 변수는 실제 비밀 값 없이 `.env.example`에 작성해 공유합니다.
- 실제 Firebase 웹 프로젝트 설정값과 서버 비밀 값은 다릅니다. 프로젝트 식별용 웹 설정을 숨기는 것으로 방 접근 권한 검증을 대신하지 않습니다.
