# 제품 및 업무 흐름 기획안

작성일: 2026-09-16 · 2차 검토일: 2026-09-17. 확인한 요구와 아직 합의하지 않은 운영 제안을 구분한다.
코드 구현이나 초기 프로젝트 설정을 포함하지 않는다. 버튼 설정의 세부 화면과 편집 방법은 후속 기획으로 남긴다.

## 1. 목적과 요구의 근거

예배인도자가 손짓이나 눈빛 대신 짧은 요청을 보내고, 방송실 담당자가 확인·처리 결과를 돌려준다.
성도들의 주의를 끌지 않으면서 누가 무엇을 원하는지 정확히 전달하는 것이 목적이다.
요청 버튼을 한 번 누르는 행동과 방송실의 응답을 중심에 두며, 직접 문장을 입력하는 기능은 보조로 둔다.

### 대화에서 확인한 요구

- 교회 방송실과 예배인도자가 실시간으로 양방향 소통한다.
- 사용자가 미리 준비한 문구의 버튼을 누르면 해당 내용이 전송된다.
- 직접 입력한 메시지도 전송할 수 있으나 요청 버튼보다 우선하지 않는다.
- 음성 통화와 영상 통화는 현재 요구하지 않는다.
- 간단한 로그인으로 사용자를 식별한다.
- 인도자는 필요할 때 개인 스마트폰을 꺼내 사용한다.
- 방송실은 Mac PC의 브라우저를 열어 사용한다.
- 버튼 설정의 구체적인 방식은 나중에 기획한다.
- 사용자는 앞서 제안한 ‘버튼 요청 → 방송실 확인·처리 → 인도자 응답 확인’의 기본 흐름에 동의했다.

### 이전 답변의 제안이며 확정되지 않은 사항

- 아이디·비밀번호, 관리자 계정 발급, 로그인 유지의 구체적인 방식.
- PWA 설치와 푸시 알림을 포함한 웹·앱 제공 방식.
- 담당자 개인 계정, 역할별 첫 화면, 요청 상태 명칭과 버튼 표시 문구.
- 예배별 참여 절차와 방송실의 공동 요청 목록.
- 개인별 버튼 이름·색상·정렬과 교회 공통 버튼 제공 방식.

아래 운영 규칙은 위 요구를 실행 가능한 흐름으로 바꾼 기획 제안이다. 사용자 확정 요구로 소급하지 않는다.

## 2. 사용자와 접근 범위

**예배인도자**는 현재 예배에 참여하고 방송실로 요청을 보낸다. 자기 요청과 자신에게 온 요청·답변을 본다.
찬양인도자, 기도자 등 실제 표시 이름과 맡은 역할을 함께 보여 동명이인이나 교대 상황을 구별한다.

**방송실 담당자**는 해당 예배의 요청을 공동으로 보고, 확인·처리하거나 인도자에게 요청한다.
개인 계정 사용을 기본 제안으로 삼아 누가 확인하고 처리했는지 기록한다.
공용 Mac에서는 교대할 때 담당자를 바꾸며, 다른 사람의 계정으로 처리 기록을 남기지 않는다.

**관리자**는 계정 이용 가능 여부, 역할 부여, 예배 생성·종료 권한을 관리한다.
관리자라는 이유만으로 모든 대화 열람 권한을 자동 부여하지 않고 운영에 필요한 범위를 별도로 정한다.
첫 버전은 한 사용자·한 회차에 인도자 또는 방송실 중 한 운영 역할을 부여하는 단순화 안을 제안한다.
다른 회차에서는 다른 역할을 맡을 수 있고 관리자 권한은 별도다. 같은 회차에서 두 역할을 동시에 쓰는 기능은 실제 필요 확인 후 검토한다.
관리 권한자가 회차별 참여자·역할을 허용한다. 목록·링크·QR이나 화면의 역할 선택만으로 입장·열람 권한이 생기지 않는다.
역할 변경 전 맡은 요청을 인계하고 이전 역할의 구독·새 알림 발송을 중단한다. 긴급 권한 회수는 인계를 기다리지 않고 먼저 차단한다.

| 행동 | 인도자 | 방송실 담당자 | 관리자 |
|---|---|---|---|
| 자기 요청 전송·후속 답변 | 가능 | 가능 | 참여 역할에 따름 |
| 방송실 공동 요청 목록 열람 | 불가 | 해당 예배에서 가능 | 별도 권한에 따름 |
| 담당 요청 확인·처리 | 받은 요청에 가능 | 공동 요청에 가능 | 참여 역할에 따름 |
| 계정·역할 관리 | 불가 | 불가 | 가능 |
| 예배 생성·접수 열기·종료 | 불가 | 권한을 받은 경우 | 가능 |

인도자끼리의 개인 대화, 교인 전체 채팅, 외부인의 공개 참여는 첫 버전에 포함하지 않는다.

## 3. 예배와 입장 흐름

‘예배 회차’는 날짜·이름·참여자를 묶어 요청을 구분하는 단위로 제안한다. 예: ‘2026-09-20 주일 2부 예배’.
‘주일 2부’라는 반복 이름만으로 식별하지 않고 실제 날짜의 회차마다 요청을 구분한다. 아래 ‘예배’는 이 회차를 뜻한다.
사용자 계정과 개인 버튼은 예배가 끝나도 유지하고, 요청과 처리 이력은 해당 회차에 남긴다.
첫 시범 운영은 한 교회의 한 실제 예배를 대상으로 하며 시험 요청은 별도 연습 회차에 남긴다.

| 회차 상태 | 허용할 행동 | 전환 기준 |
|---|---|---|
| 준비 | 허용된 사람의 참여·조회 | 관리 권한자가 날짜·역할을 정함 |
| 진행(접수 열림) | 새 요청·안내·답변과 처리 | 권한 있는 사람이 방송실 수신 준비를 확인하고 엶 |
| 종료 | 기존 권한 범위의 조회만 | 미해결 요청을 확인하고 권한 있는 사람이 닫음 |

‘진행’은 실제 예배 시작 시각과 다르다. 예배 전 실제 모니터 조정도 접수를 미리 열어 요청할 수 있다.
연습 회차에도 별도의 상태·참여 권한을 적용하고 연습 요청을 실제 회차로 옮기지 않는다. 종료 회차 재개는 첫 버전에서 보류한다.

1. 관리 권한이 있는 사람이 예배를 준비하고 방송실 담당자가 참여한다.
2. 인도자가 최초 로그인 후 참여 가능한 현재 예배를 확인한다.
3. 예배 이름과 자기 표시 이름·역할을 확인하고 참여한다.
4. 인도자는 자기 요청 버튼 화면, 방송실 담당자는 공동 요청 목록으로 들어간다.
5. 별도 연습 회차에서 전송·응답을 점검한 뒤 실제 회차의 날짜·역할을 다시 확인한다.
6. 예배 도중 앱을 다시 열면 같은 예배로 돌아가 최신 요청·응답을 불러온다.
7. 종료된 예배라면 종료 사실을 표시하고 다음 예배를 확인하게 한다.

동시에 참여 가능한 예배가 여러 개라면 날짜·이름으로 직접 선택한다. 선택 변경은 이전 회차 권한을 새 회차로 옮기지 않는다.
마지막 접속 예배를 다음 주 예배로 간주해 자동 전송하지 않는다.
방송실이 연결되어 있는지와 담당자가 실제로 응답할 준비가 되었는지는 다른 정보로 취급한다.
방송실 담당자가 없는 경우 ‘담당자 접속 없음’을 표시하고, 보낸 요청이 곧 처리될 것처럼 안내하지 않는다.
예배 입장 방식은 링크·QR·목록 중 후속 결정하되, 로그인 권한 확인을 대신하지 않는다.

## 4. 대표 시나리오

### 인도자가 요청하고 방송실이 처리

1. 인도자가 ‘모니터 크게’를 누른다.
2. ‘제 모니터 스피커 소리를 키워주세요’라는 요청에 요청자와 예배 정보를 붙여 전송한다.
3. 인도자에게 서버 접수 여부를 표시하고, 방송실 공동 목록에는 미확인 요청을 표시한다.
4. 방송실 담당자 A가 ‘확인했어요’를 누르면 담당자가 기록되고 인도자에게 확인 상태가 보인다.
5. 담당자가 실제 조정 후 ‘조정했어요’를 누르면 처리 완료로 바뀐다.
6. 인도자는 필요하면 ‘이제 괜찮아요’ 또는 직접 입력으로 결과를 덧붙인다.

‘조정했어요’는 방송실의 작업 완료다. 실제 청취 결과까지 만족한다는 뜻은 아니다.
‘이제 괜찮아요’는 선택적인 회신으로 두어 인도자가 매번 휴대폰을 다시 꺼내지 않아도 된다.
추가 설명·만족 회신은 원 요청의 답변이며 새 작업을 만들지 않는다. 완료 후 추가 조정은 원 요청에 연결된 새 요청으로 제안한다.
새로 보내는 시점에 같은 회차의 접수·참여 권한이 유효해야 한다. 종료 회차의 요청을 다음 회차에 자동 복사하지 않는다.

### 방송실이 인도자에게 요청

1. 방송실 담당자가 현재 예배의 인도자를 선택한다.
2. ‘마이크를 조금 가까이 해주세요’ 같은 준비된 문구나 직접 입력한 요청을 보낸다.
3. 해당 인도자에게 요청을 표시하고, 인도자가 누른 확인·처리 응답을 방송실에 돌려준다.
4. 화면이 잠겨 있으면 알림을 시도하되, 사람이 실제 확인한 시각과 구별한다.

첫 버전의 방송실 발신 대상은 특정 인도자 한 명으로 제안한다.
여러 사람에게 동시에 보내는 요청은 대상별 확인 상태가 필요하므로 후속 범위로 둔다.

### 행동 요청·단순 안내·답변의 차이

‘모니터를 키워주세요’는 행동 요청으로 확인 후 완료·처리 불가 응답이 필요하다. 버튼과 직접 입력 모두 같은 규칙을 쓴다.
‘다음 순서는 성경봉독입니다’ 같은 단순 안내는 수신자의 명시적 확인으로 끝내고 조정 완료를 요구하지 않는 안을 제안한다.
전송 시 요청과 안내 종류를 구분해 저장한다. 담당자가 문장만 보고 종류를 추측하거나 읽었다는 이유로 자동 완료하지 않는다.
빠른 버튼은 요청, 방송실의 안내 보내기 경로는 안내를 기본값으로 삼아 종류 선택을 매번 추가하지 않는다. 버튼 설정 세부는 후속 기획에 남긴다.
기존 요청의 답변은 그 아래에 붙이고 별도 담당 배정·완료를 요구하지 않는다. 자유 입력만 가능한 채팅방을 첫 화면으로 만들지 않는다.

## 5. 전송 상태와 처리 상태

전송 상태는 시스템이 어디까지 접수했는지, 처리 상태는 사람이 어디까지 진행했는지를 나타낸다.
두 상태를 따로 기록하되 화면에서는 현재 필요한 상태를 짧은 문구로 보여준다.

| 전송 상태 | 의미 | 사용자가 할 수 있는 일 |
|---|---|---|
| 전송 중 | 서버 접수 응답을 기다리는 중 | 상태 확인 |
| 서버 접수 | 요청을 서버에 저장함 | 담당자 확인 기다리기 |
| 접수 여부 확인 중 | 응답이 없어 접수 여부를 단정할 수 없음 | 연결 회복 후 같은 요청 확인 |
| 전송 안 됨 | 접수되지 않았음이 확인됨 | 요청이 유효하면 재전송 |

| 처리 상태 | 의미 | 상태를 바꾸는 행동 |
|---|---|---|
| 미확인 | 사람이 아직 명시적으로 확인하지 않음 | 수신 담당자가 확인 |
| 확인·처리 중 | 담당자가 요청을 맡음 | 담당자가 완료 또는 처리 불가 선택 |
| 처리 완료 | 담당자가 실제 조치를 마침 | 요청자의 선택적 결과 회신 |
| 확인 완료(안내) | 안내 수신자가 명시적으로 확인함 | 추가 조정 완료 불필요 |
| 처리 불가 | 지금 조치할 수 없음 | 이유를 짧게 전달 |
| 취소됨 | 요청자가 더 이상 조치를 원하지 않음 | 취소 이력을 표시 |
| 종료로 마감 | 예배 종료까지 해결되지 않음 | 다음 예배로 자동 이월하지 않음 |

앱 열기·알림 수신·화면 표시만으로 사람 확인을 기록하지 않는다. 요청은 확인 후 처리로, 안내는 확인 완료로 이어진다.
완료·확인 완료·처리 불가·취소·종료로 마감은 종결 상태다. 진행 중인 회차에서는 답변을 덧붙일 수 있지만 종결 상태를 되돌리지는 않는다.

## 6. 예외와 운영 규칙 제안

**실수로 연속 누름:** 전송 중인 동일 버튼에는 진행 상태를 표시해 연타를 줄인다.
통신 재시도로 같은 요청이 두 번 접수되지는 않게 한다. 이후 의도적으로 반복한 요청까지 영구 차단하지 않는다.

**연결이 끊김:** 서버 접수 여부가 불명확하면 성공이나 실패로 단정하지 않는다.
재접속 시 접수된 요청과 상태부터 확인하고, 아직 미접수인 오래된 요청은 자동으로 새로 보내지 않는다.
예를 들어 지난 찬양의 ‘모니터 크게’가 설교 중 뒤늦게 실행되는 일을 피해야 한다.
사용자가 지금도 필요한 요청임을 확인하여 재전송하도록 제안한다.

**잘못 누른 요청 취소:** 종결 전 요청·안내만 취소하며 기록은 삭제하지 않는다. 처리 중이면 담당자에게 취소를 별도로 알린다.
취소와 완료가 겹치면 먼저 저장된 상태를 유지하고 뒤의 변경으로 덮어쓰지 않는다. 취소가 실제 조정을 되돌렸다고 안내하지 않는다.
취소가 먼저 저장됐어도 실제 조정이 이미 이루어졌다면 담당자는 그 사실을 답변으로 남긴다. 추가 변경은 새 요청으로 받는다.
회차까지 종료돼 답변을 남길 수 없으면 현장 운영 기록에 실제 조정 여부를 남긴다. 이를 위해 종료 상태를 다시 열지 않는다.

**방송실 여러 담당자:** 처음 확인한 사람을 담당자로 기록하고 다른 담당자에게도 즉시 보인다.
이미 맡은 요청을 다른 사람이 또 확인하면 현재 담당자를 안내한다.
정상 교대는 명시적으로 인계하고 변경 이력을 남긴다. 일시 연결 끊김만으로 담당자를 자동 해제하지 않는다.
명시적 이탈·권한 회수 등으로 인계할 수 없으면 맡은 요청에 ‘인계 필요’를 표시한다. 이는 새 처리 상태가 아닌 담당 정보다.
해당 회차의 방송실 역할과 재배정 권한을 가진 책임자가 실제 조정 상황을 확인하고, 사유·이전 담당자·새 담당자를 기록해 재배정한다.
관리자 권한만으로 대화 열람을 허용하지 않는다. 재배정할 사람도 없으면 현장 대체 연락으로 처리하고 시스템에서 해결됐다고 표시하지 않는다.

**처리 불가:** 이번 요청을 수행할 수 없으면 ‘처리할 수 없어요’와 짧은 이유를 보내 종료한다.
잠시 기다려야 하지만 나중에 조정할 예정이라면 직접 답변으로 사유를 알리고 처리 중 상태를 유지한다.
미확인 상태로 방치하는 것과 구분하여 인도자가 같은 요청을 반복하지 않게 한다.

**인도자가 화면을 닫음:** 방송실의 처리 결과는 저장한다. 다시 열면 알림 수신 여부와 관계없이 확인한다.
잠금 상태 알림의 도착만으로 사람 확인을 보장하지 않으며, 기기별 실제 사용 검증은 별도로 한다.

**상대 부재·무응답:** 회차 참여 권한이 유효하면 미접속 상대에게도 접수할 수 있지만 미확인으로 남긴다. 접근 권한이 없는 대상에는 새로 보내지 않는다.
요청 시간·경과와 접속 정보를 보여 주고 재촉 요청을 자동 생성하지 않는다. 언제 대체 연락으로 전환할지는 현장 합의로 정한다.
접수된 지 오래된 요청은 처리 전에 최근 답변이나 현장 연락으로 지금도 필요한지 확인한다. 무응답을 동의·만족·완료로 바꾸지 않는다.

**예배 종료:** 미해결 요청 수를 보여준 뒤 권한 있는 사람이 종료한다.
완료 이력은 유지하고 남은 요청은 ‘종료로 마감’으로 구분한다. 처리 완료로 일괄 변경하지 않는다.
종료와 새 요청·답변·상태 변경이 겹치면 서버에 먼저 확정된 순서를 따른다. 종료 뒤 도착한 변경은 거절하고 최신 결과를 보여 준다.
종료 후 조회도 남아 있는 접근 권한 안에서 허용한다. 조회 기간과 삭제 시점은 운영 기획에서 정한다.

## 7. 첫 버전과 후속 범위

첫 버전에서 검증할 묶음은 다음과 같다.

- 로그인, 사용자 이름 표시, 역할과 예배 참여 권한.
- 예배 준비·접수 열기·참여·종료 및 현재 회차 식별.
- 개인별 준비된 요청 버튼과 직접 입력 요청, 요청별 답변.
- 버튼을 사전에 저장·수정하는 최소 기능. 구체적인 편집 화면·구성은 후속 기획 후 구현한다.
- 인도자 스마트폰 화면과 방송실 Mac 브라우저 화면.
- 양방향 요청·안내·답변, 종류별 확인·완료, 처리 불가·취소 및 담당 인계 이력.
- 접수 여부 표시, 재접속 후 복구, 중복 접수 방지.
- 잠금 화면 응답 알림의 실기기 검증과 안내. 일반 운영 출시 범위는 검증 결과를 보고 확정한다.

버튼 편집 세부 UX는 다음 기획 단계에서 다루며, 최소한의 개인 버튼 생성·수정·보존은 첫 버전에 포함한다.
첫 버전 이후의 고도화 후보는 여러 예배 동시 운영, 공통 버튼 배포·공유, 다수 수신자 요청,
통계 화면, 외부 서비스 연동, 앱스토어 배포 여부다. 음성·영상은 새 요구가 생길 때 다시 판단한다.
푸시가 준비되지 않은 내부 시험과 개인 스마트폰을 수시로 넣어 두는 실제 예배 운영의 준비 상태를 구별한다.

## 8. 핵심 사용자 수용 조건

1. 로그인과 회차 참여 권한이 유효하고 접수가 열린 경우 첫 화면의 버튼 한 번으로 요청하며, 링크만 아는 비참여자는 접근하지 못한다.
2. 방송실은 요청자·요청 내용·예배·시간을 구분하고 미확인 요청을 찾아볼 수 있다.
3. 서버 접수만 된 요청이 사람 확인이나 처리 완료로 표시되지 않는다.
4. 요청의 확인·완료·처리 불가와 안내의 확인 완료를 구분하고 재접속 후에도 같은 결과를 표시한다.
5. 방송실이 특정 인도자에게 보낸 요청은 다른 인도자의 개인 수신함에 섞이지 않는다.
6. 같은 통신 요청을 재시도해도 방송실에 별개의 새 요청이 추가되지 않는다.
7. 연결이 끊긴 동안 미접수인 오래된 요청은 연결 회복만으로 뒤늦게 전송되지 않는다.
8. 동시 확인의 담당자는 한 명이며, 담당자 권한 회수 후 이전 접근은 차단되고 책임자의 재배정 이력으로 인계를 복구할 수 있다.
9. 취소와 완료 경합에서 먼저 확정된 상태를 유지하고 실제 조정 사실을 별도로 확인할 수 있다.
10. 예배 종료 시 미해결 요청을 완료로 바꾸지 않으며, 뒤늦은 답변·새 요청·상태 변경과 다음 예배 자동 이월을 막는다.
11. 개인 버튼과 종결 이력을 보존하고 추가 조정은 접수가 열린 같은 회차의 연결된 새 요청으로 만들며, 다른 회차 기록과 섞지 않는다.
12. 상대 미접속·무응답, 인도자의 휴대폰 잠금·복귀, 방송실 Mac을 함께 시험하고 사람 확인을 추정하지 않는다.

- 첫 시범 예배의 참여자 수, 같은 회차 복수 역할의 실제 필요, 교대·재배정 책임자.
- 회차별 참여 권한 부여, 요청 접수를 여닫는 담당자, 링크·QR·목록 중 참여 진입 방식.

- 요청·안내 구분과 완료 후 연결된 새 요청이 현장 사용에 맞는지, 무응답 때 대체 연락으로 전환할 기준.
- 요청·답변 보관 기간, 열람 가능 인원, 종료된 예배 조회 범위.
